# Учёт занятий — кабинет репетитора

Личный кабинет репетитора: расписание, отметки «Провёл», заработок, ученики и ставки, пакеты
предоплаты, а также кабинеты для родителей и учеников (по личной ссылке). Всё на русском,
рассчитано в первую очередь на телефон.

- Сайт: **https://tviitterggl-dev.github.io/tutor-dashboard/** (кабинет учителя)
- Кабинет родителя/ученика: `…/cabinet.html#p=<ключ>` или `#s=<ключ>` (ссылку выдаёт учитель)
- История правок, проблемы и решения — в [`DEVLOG.md`](DEVLOG.md). **Этот README описывает
  текущее состояние.**

## Архитектура

Бэкенда нет. Это статические страницы, которые браузер открывает с **GitHub Pages**. Данные хранит
**Firebase Firestore**, запись и чтение идут напрямую из браузера. Доступ ограничивают правила
Firestore и **Firebase Authentication** (email + пароль учителя). Всё бесплатно: Firebase на тарифе
Spark, файлы ДЗ в Cloudinary (unsigned preset). Сборки нет: HTML/CSS/JS в файлах как есть,
библиотеки (Firebase SDK, FullCalendar, html2canvas) подключаются с CDN.

```
 учитель (index.html) ──Auth──► Firestore teacherSpaces/{uid}/…   (только владелец)
        │ публикует «витрины»        │
        ▼                            ▼
 parentAccess/{ключ}, studentAccess/{ключ}  ◄── читает кабинет родителя/ученика (cabinet.html)
 channels/{ключ канала}/items               ◄── кабинет пишет: ДЗ, заявки, «оплачено», «пояснение»
        └──── учитель читает каналы, проверяет и применяет к занятиям ────┘
```

- **Учитель** входит по email и паролю, его данные лежат в `teacherSpaces/{uid}`.
- **Родитель или ученик** входит без аккаунта, по секретному ключу в ссылке. Ключ открывает только
  «витрину» — готовую выжимку по одному ребёнку, которую публикует кабинет учителя: его занятия,
  отчёты, ДЗ, пакет, ссылки на созвон и доску. Чужие занятия видны только как «занято», без имён.
- Родитель и ученик **ничего не меняют напрямую**. Они добавляют сообщения в канал, а кабинет учителя
  проверяет, что занятие принадлежит этому ученику, и применяет: ДЗ и «пояснение» переносятся в
  занятие, «оплачено» ставится отметкой, заявки на перенос или отмену ждут решения учителя.
- Отзыв доступа удаляет витрину и заводит новые ключи каналов.

## Где что лежит

| Файл | Что это |
|---|---|
| `index.html` | Кабинет учителя: разметка, стили и весь код в одном файле. Вкладки: Занятия (День/Неделя), Календарь (редактор на FullCalendar), Заявки, Итоги, Ученики (профили, пакеты, доступы), Расписание (PNG свободных окон), Ещё (резервная копия, тема). |
| `cabinet.html` | Кабинет родителя/ученика: Занятия, Календарь, ДЗ, Заявки, Ещё. |
| `design.css` | Дизайн-система: цвета светлой/тёмной темы, шрифты Spectral/Manrope, скругления, тени, анимации. Общая для обеих страниц. |
| `theme.js` | Тема: как в системе / выбрана вручную (`localStorage["theme"]`), ставится до отрисовки. |
| `firestore.rules` | Правила доступа к базе. **Меняются в Git, но на сервер попадают только после деплоя** (см. ниже). |
| `firebase.json` | Настройки CLI `firebase`: путь к правилам, порт эмулятора. |
| `sw.js`, `manifest.json`, `icons/` | Установка кабинета учителя как приложения (Android/iPhone). |
| `tests/` | Автотесты: e2e в Playwright с подменённым Firebase и проверка правил в эмуляторе. На сайт не влияют. |
| `DEVLOG.md` | Хронология изменений; там же шпаргалка по разовым шагам в консоли Firebase. |

## Данные (Firestore)

```
teacherSpaces/{uid}/state/main
    marks{lessonId: {marked, overrideAmount, lockedRate}}        — «Провёл» и суммы
    pkgOverrides{"Имя, N класс": {...}}                          — ручные правки пакетов
    studentProfiles{"Имя[ Фамилия], N класс": {name, surname, cls, rate, callUrl, accessUrl, notes, hidden}}
    studentChannels{studentId: {shared, parent}}                 — ключи каналов
teacherSpaces/{uid}/lessons/{id}
    title «Имя[ Фамилия] N класс[ k/M]», studentId, startMs, endMs, status (planned|done|cancelled|rescheduled),
    report, homework[], paid{value,by,at}, callUrl, familyNote{text,by,at}, kind:"personal" (личное время) …
teacherSpaces/{uid}/accessKeys/{ключ}   role, studentId, label, active, revokedAt
teacherSpaces/{uid}/requests/{id}       решения по заявкам
parentAccess/{ключ}, studentAccess/{ключ}   витрины (перезаписываются кабинетом учителя)
channels/{ключ}/items/{id}              homework | reschedule | cancel | paid | note (только создание)
```

Ученик определяется строкой `"Имя, N класс"`. Фамилия становится частью этой строки
(`"Имя Фамилия, N класс"`), только если её указали при добавлении ученика: так можно завести двух
«Маш, 7 класс». У остальных учеников фамилия хранится в профиле только для показа. Названия занятий
при этом не меняются: старые занятия, импортированные из Google Календаря, так и называются
«Имя N класс».

Резервная копия всех данных — вкладка «Ещё» → «Скачать резервную копию данных» (JSON). Там же
таблица занятий для Excel (CSV).

## Тесты

Нужны Node.js 20+; для проверки правил — ещё Java 11+ и `firebase-tools`.

```bash
cd tests
npm install                 # Playwright, FullCalendar, html2canvas (браузер Chromium — один раз: npx playwright install chromium)
npm run test:e2e            # e2e: оба кабинета в Chromium, Firebase/Cloudinary/CDN подменены (tests/stubs)
npm run test:rules          # firestore.rules в локальном эмуляторе
node check-syntax.mjs ../index.html ../cabinet.html   # синтаксис встроенных скриптов
node screens.mjs <папка> [папка со шрифтами]           # скриншоты экранов на «iPhone» (до/после правок дизайна)
```

Тестовый стенд `tests/e2e/harness.mjs` поднимает локальный сервер и подменяет Firebase: «база»
хранится в `localStorage["__fakeDb"]`, упрощённые правила в заглушке пускают в
`teacherSpaces/{uid}` только вошедшего. Сеть в тестах закрыта: всё, что не подменено, блокируется.

## Как выложить

- **Сайт**: всё, что попало в ветку `main`, GitHub Pages публикует сам примерно за 1–2 минуты.
  Никакой сборки нет.
- **Правила базы** (только если менялся `firestore.rules`) — выкладывает владелец Google-аккаунта
  проекта со своего компьютера:
  ```bash
  git pull
  firebase login          # один раз
  firebase deploy --only firestore:rules --project tutor-cabinet
  ```
  Пока новые правила не выложены, новые функции, которые на них опираются, выдают в кабинете
  понятное сообщение, а не ошибку.

## Правила проекта

- Никаких платных сервисов и своего сервера.
- **Секреты не коммитим**: реальные ключи доступа, uid, email, токены. В тестах только вымышленные
  значения; тест `access.test.mjs` проверяет, что в коде нет старого ключа. Перед коммитом
  просматриваем изменения на секреты.
- Каждое изменение: тесты (`npm run test:e2e`, при правке правил ещё `npm run test:rules`) и запись
  в `DEVLOG.md`.
- Интерфейс и тексты — на русском, в первую очередь для телефона.
