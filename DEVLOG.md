## Шпаргалка

### Как устроен проект
- `index.html` — кабинет учителя (один файл: разметка + стили + код).
- `cabinet.html` — кабинет родителя/ученика (открывается по личной ссылке,
  дальше запоминается на устройстве; «Забыть это устройство» — внизу).
- `design.css` — дизайн-система по стиль-гайду (цвета светлой/тёмной темы,
  шрифты Spectral/Manrope, скругления, тени, анимации) — общая для обеих
  страниц. `theme.js` — выбор темы (как в системе / вручную, запоминается
  на устройстве) и ползунок во вкладке «Ещё».
- `sw.js`, `manifest.json`, `icons/` — установка как приложение.
- `firestore.rules` — правила доступа к базе Firestore. **Меняются в Git, но
  на сервер попадают только после команды деплоя** (см. ниже).
- `firebase.json` — настройки для команды `firebase` (где лежат правила,
  порты эмулятора).
- `tests/` — автотесты (в браузере с подменёнными Firebase/Cloudinary/CDN и
  проверка правил в локальном эмуляторе). На сайт не влияют.
- Вход учителя — **Firebase Authentication (email + пароль)**, данные в
  `teacherSpaces/{uid}`. Google-входа, чтения Google Календаря и Google
  Таблицы в проекте больше нет (с 2026-09-25).
- Сайт: GitHub Pages из ветки `main` → https://tviitterggl-dev.github.io/tutor-dashboard/
  (обновляется примерно через 1–2 минуты после push в `main`).

### Включить вход по email в Firebase (один раз, делает владелец проекта)
Консоль Firebase → проект `tutor-cabinet` → **Authentication** → «Get
started» (если ещё не нажимали) → вкладка **Sign-in method** → **Email/Password**
→ включить первый переключатель (Email/Password; «Email link» не нужен) →
**Save**. Проверка из облачной сессии (без пароля):
```
curl -s -X POST -H 'Content-Type: application/json' \
  "https://identitytoolkit.googleapis.com/v1/accounts:signInWithPassword?key=<apiKey>" \
  --data '{"email":"nobody@example.invalid","password":"x","returnSecureToken":true}' | jq .error.message
# CONFIGURATION_NOT_FOUND — Authentication не включён; OPERATION_NOT_ALLOWED — не включён Email/Password;
# EMAIL_NOT_FOUND / INVALID_LOGIN_CREDENTIALS — всё включено.
```
По желанию, после создания своей учётной записи: Authentication → Settings →
User actions → снять «Enable create (sign-up)», чтобы новые учётные записи
больше никто не заводил. Посторонние и так не видят чужих данных (правила
пускают только в свою папку), это просто порядок.

### Задеплоить правила Firestore (делает владелец Google-аккаунта)
В обычном терминале (PowerShell) на своём компьютере:
```
cd Desktop\tutor-dashboard
git pull
firebase deploy --only firestore:rules --project tutor-cabinet
```
Ждать строку `Deploy complete!`. Если `firebase` пишет, что не залогинен —
сначала `firebase login` (откроется браузер, войти под аккаунтом, где проект
`tutor-cabinet`). Если `firebase` не найден — `npm install -g firebase-tools`.

Из облачной сессии Claude Code это сделать нельзя: `firebase login` требует
входа в Google-аккаунт владельца, а сеть облачной сессии не пускает на
`auth.firebase.tools` (ответ прокси 403).

### Прогнать тесты (на любом компьютере с Node.js и Java)
```
cd tests
npm install
npm run test:rules   # правила в эмуляторе Firestore (нужна Java; эмулятор скачается сам)
npm run test:e2e     # сайт в Chromium с заглушками Google/Firebase/Cloudinary
node check-syntax.mjs ../index.html ../cabinet.html   # быстрая проверка синтаксиса
```
Для e2e нужен Chromium для Playwright (`npx playwright install chromium`, в
облачной сессии уже установлен).

### Проверить базу напрямую (без браузера)
Firestore REST API, ключ API — из `firebaseConfig` в `index.html` (он
публичный, это нормально для Firebase). Данные учителя без входа не
читаются: нужен токен (`idToken`) из входа учителя —
`accounts:signInWithPassword` с её email и паролем, из облачной сессии
этого не сделать. Без входа видны только витрины кабинетов и каналы, если
знать их ключи:
```
K=<apiKey>
B='https://firestore.googleapis.com/v1/projects/tutor-cabinet/databases/(default)/documents'
curl -s "$B/parentAccess/<ключ родителя>?key=$K" | jq '.fields | keys'
curl -s "$B/teacherSpaces?key=$K" | jq '.error.status'   # PERMISSION_DENIED
# с токеном учителя: curl -H "Authorization: Bearer $ID_TOKEN" "$B/teacherSpaces/$UID/state/main"
```
Важно: в bash путь с `(default)` надо брать в одинарные кавычки, иначе
`syntax error near unexpected token '('`.

### Модель данных Firestore
```
teacherSpaces/{uid}/state/main               отметки «Провёл» (marks), правки пакетов (pkgOverrides),
                                              профили учеников (studentProfiles: name, cls, rate,
                                              callUrl, accessUrl, notes), каналы (studentChannels)
teacherSpaces/{uid}/lessons/{id}              занятие: title, studentId ("Имя, N класс"), startMs/endMs,
                                              start/end (ISO, +03:00), date, time, durationMin,
                                              status: planned|done|cancelled|rescheduled,
                                              packageId, recurrenceId, source: gcal|app,
                                              report, homework[{url,name,by}], rescheduledFrom/To,
                                              paid {value,by,at}, callUrl (разовая ссылка на созвон)
teacherSpaces/{uid}/accessKeys/{key}          реестр выданных ключей: role, studentId, label,
                                              createdAt, active, revokedAt
teacherSpaces/{uid}/requests/{id}             решения по заявкам: type, lessonId, studentId, status
                                              approved|rejected, reason, old/newStartMs, decidedAt
parentAccess/{key}, studentAccess/{key}       «витрина» для кабинета: занятия одного ученика (с id),
                                              отчёты, домашка, пакет и paid (родителю), busy[] без
                                              имён, requests (решения), channel, parentChannel
channels/{ключ канала}/items/{id}             сообщения из кабинетов: homework | reschedule |
                                              cancel | paid (только создание, см. правила)
```
Занятия, когда-то импортированные из Google Календаря, имеют id = id
события, поэтому старые отметки «Провёл» (marks, тоже по id события)
продолжают работать.

Личное время хранится там же, в `lessons`, с полями `kind: "personal"`,
`note` (комментарий только для учителя) и `studentId: null`.

## 2026-09-26 (3) — пуши включены (ключ VAPID) + 9 правок интерфейса и логики

- **Пуши**: в `cabinet.html` вписан публичный ключ Web Push (`FCM_VAPID_KEY`). Сервисный аккаунт уже
  лежит в секретах GitHub, правила выложены, поэтому пуши теперь работают полностью. Тестовый стенд
  подставляет свой ключ регуляркой (`opts.vapidKey`, пустая строка — «ключа нет»).

**1. Файлы ДЗ — перетаскивание и вставка из буфера.**
- В обоих кабинетах вместо «Обзор…» теперь зона `.drop-zone`: перетащить фото или файл, нажать и
  выбрать, либо вставить скриншот (Ctrl+V).
- Картинка из буфера («image.png») получает имя «скриншот-ДД-ММ-ЧЧ-ММ.png».
- Вставка идёт в зону, которая сейчас в фокусе. Если в фокусе ничего нет — в текущее занятие окна;
  в кабинете на вкладке «ДЗ» — в выбранное занятие.
- При открытии и закрытии окна цель вставки сбрасывается, поэтому скриншот не уйдёт в занятие,
  открытое раньше.

**2. «Оплачено» у родителя — кнопка-переключатель прямо в карточке занятия** (в списке «Ближайшие»
и «История»), в стиле «Провёл».
- Надписи: «Оплачено» → «✓ Оплачено (снять)». После отметки в карточке появляется «Благодарю за
  оплату!» (на 8 секунд), в окне занятия — то же сообщение.
- Нажатие на кнопку окно занятия не открывает.
- Для родителя бейдж «оплачено» заменён кнопкой.

**3. «Отчёт»** — бывшее «Сохранить отчёт». Отчёт публикуется, и родителю и ученику автоматически
уходит уведомление с его текстом.
- Уведомление устроено как «Отправить сейчас»: `mode: "now"`, адресат — ученик целиком,
  `source: "report"`. В кабинете оно видно сразу, пуш уходит с ближайшей рассылкой.
- Повторное нажатие без изменений второе уведомление не шлёт. Пустой отчёт — «убрать», без
  рассылки. Если у ученика нет доступа к кабинету — отчёт только сохраняется.

**4. Отмена занятия пакета.**
- Разбор: в коде при отмене **ничего не сдвигалось** — занятие просто помечалось «отменено».
  Пакет терял занятие (оплачено 8, пройдёт 7), и его приходилось добивать вручную.
- Решение: в окне занятия у занятия пакета есть галочка «при отмене — замена в конец пакета»,
  по умолчанию включена. `cancelWithMakeup()`:
  - **даты других занятий не трогаются**;
  - у следующих занятий ЭТОГО пакета номер уменьшается на 1 (7/8 → 6/8, 8/8 → 7/8);
  - в конец добавляется одна замена «8/8» — через неделю после последнего занятия пакета, в то же
    время (если занято — ещё на неделю позже);
  - на отменённом занятии хранится `makeup {id, renumbered}`.
- «Вернуть занятие» (`restoreWithMakeup`) удаляет замену, если она ещё не проведена, и возвращает
  номера.
- При подтверждении заявки родителя на отмену занятия пакета — вопрос «Добавить замену в конец
  пакета?».

**5. «Провёл» ↔ пакет.** Две причины, почему приходилось править пакет вручную:
- (а) пакеты считались только по занятиям за последние 3 недели — при занятиях раз в неделю первые
  проведённые выпадали. Теперь подсчёт за полгода (`fetchPackageEvents`: −180/+240 дней); кабинеты
  родителей считают так же;
- (б) «Исправить» записывал абсолютное число (`doneOverride`), и оно замирало. Теперь это поправка
  `doneAdjust` к автоподсчёту, и следующие отметки «Провёл» прибавляются сами. Старые правки
  переносятся один раз без изменения видимых чисел (`migratePackageOverrides`);
- пакет, добавленный вручную, считает отметки «Провёл» этого ученика, поставленные после его
  добавления (`doneBase` + отметки с `updatedAt ≥ countFrom`);
- после любой отметки пересчитываются пакеты во вкладке «Ученики», плашка «пакет заканчивается»
  и кабинеты родителей.

**6. Карточка занятия у учителя открывается по нажатию в любом месте** (кроме поля суммы, кнопок
и ссылок).

**7. «ДЗ к следующему занятию»** — отдельный блок в окне занятия. Он находит следующее
запланированное занятие ЭТОГО ученика по `studentId` (с учётом фамилии, тёзки не путаются),
показывает дату и уже прикреплённые файлы и даёт свою зону для файлов.

**8. Шапка:**
- «Занятия: в дашборде» и почта перенесены во вкладку «Ещё» → «Аккаунт и база»;
- кнопка «выйти» из шапки убрана — выход есть в «Ученики» → «Аккаунт»;
- ошибка базы («База: не сохранилось!») видна наверху отдельной плашкой `#syncAlert` (по нажатию
  страница обновляется).

**9. Поле отчёта** — во всю ширину окна и выше (160px). На телефоне ≥ 45% экрана и шрифт 16px,
чтобы iPhone не приближал страницу.

## 2026-09-26 (2) — конструктор уведомлений: вкладка «Уведомления», показ в кабинетах, пуши через GitHub Actions

**Что можно** (вкладка «Уведомления» у учителя, никакой автоматической логики «когда что слать»):
- свой текст, можно с подстановками `{ученик}`, `{дата}`, `{время}` — они заполняются для конкретного
  занятия;
- «когда»:
  - **разово** — показать при следующих N открытиях кабинета (N задаётся) и один раз отправить пуш;
  - **перед каждым занятием** — за любое число минут, часов или дней: 90 минут, 1,5 часа, 26 часов,
    сутки;
- «кому»: все / все родители / все ученики / ученик целиком / его родители / его ученик /
  конкретный человек по ключу доступа (мама отдельно от папы);
- для одного ученика — **к каким занятиям**: ко всем или только к отмеченным в списке его ближайших
  занятий;
- «и пуш на телефон» — галочка;
- список настроенных уведомлений: изменить, выключить или включить, удалить; у каждого статус пушей
  (сколько рассылок, на сколько устройств, когда была последняя);
- **«Отправить сейчас»** — произвольный текст выбранному адресату. В открытом кабинете сообщение
  появляется сразу, пуш уходит с ближайшей фоновой рассылкой;
- карточка «Пуш на телефон»: сколько устройств подписано у каждого ученика и когда был последний
  запуск фоновой рассылки.

**Как устроено:**
- `notify-core.js` — общая логика: адресаты (`keyMatches`), занятия правила (`ruleLessons`), что
  опубликовать в витрину (`noticesForKey`), какие напоминания показать сейчас (`dueReminders`),
  какие пуши отправить (`planPushes`). Один и тот же файл работает в обоих кабинетах и в `notifier/`.
- Данные: `teacherSpaces/{uid}/notifications/{id}` (правила: только учитель, `validNotification`)
  и `notifLog/{id}` (журнал рассылки: учитель только читает, пишет сервисный аккаунт).
- **В кабинете**, без сервера:
  - учитель публикует в витрину каждого адресата только его `notices`;
  - кабинет показывает карточки «Сообщение от преподавателя» и «Напоминание о занятии»;
  - счётчик «N раз» и «Понятно, скрыть» хранятся на устройстве отдельно для каждой ссылки (на общем
    планшете мама и ребёнок считаются по отдельности);
  - напоминание висит с момента «за X» до конца занятия, кабинет перепроверяет его раз в минуту.
- **Пуш**:
  - в «Ещё» кабинета есть «Уведомления на телефон» → «Включить». Кабинет регистрирует `sw.js`,
    просит разрешение, получает токен FCM (`firebase-messaging`, публичный ключ `FCM_VAPID_KEY`)
    и пишет в общий канал ученика сообщение `type: "push"` с токеном и ключом доступа;
  - есть «Проверить» (локальное уведомление) и «Выключить»; «Забыть это устройство» тоже удаляет
    подписку;
  - на iPhone без экрана «Домой» кабинет объясняет, что сделать.
- `sw.js` (кэш `tutor-shell-v3`) обрабатывает `push`: показывает уведомление из `data`
  {title, body, url, tag}. По `notificationclick` открывает кабинет по ссылке с ключом.
- Учитель: `processChannel` не трогает `push`-сообщения. При отзыве доступа `rotateChannels`
  переносит в новый канал подписки только действующих ключей.
- **Фоновая рассылка** `notifier/send.mjs`, `firebase-admin`, работает с правами сервисного аккаунта:
  - запускается из `.github/workflows/notify.yml` по cron `*/15 * * * *` и вручную (Run workflow);
    одновременно идёт только один запуск (`concurrency`);
  - для каждого учителя читает уведомления, ключи, занятия, подписки в каналах и журнал, строит
    план через `planPushes` и шлёт `messaging.sendEach`;
  - запись в журнале создаётся **до** отправки через `create()`, поэтому два параллельных запуска
    не дублируют уведомления;
  - мёртвые токены удаляются;
  - напоминание, опоздавшее больше чем на 3 часа, не шлётся; «сейчас» старше 3 дней тоже;
  - в `state/main.notifier.lastRunAt` пишет время запуска, учитель видит его во вкладке;
  - без секрета `FIREBASE_SERVICE_ACCOUNT` скрипт завершается зелёным и ничего не шлёт.
- **Правила** `firestore.rules`: коллекции `notifications` и `notifLog`, тип `push` в `validItem`
  (token 20–4096 символов, key 24–64; `token`/`key` разрешены только у `push`). **Нужен деплой.**

**Попутно исправлено:**
- **ошибка из прошлой записи:** `addItem` в кабинете выбрасывал пустые строки, поэтому «убрать
  пояснение» ушло бы без `comment`, и настоящие правила такую запись отклонили бы. Тестовая заглушка
  этого не видела. Теперь заглушка Firestore проверяет сообщения каналов так же, как `validItem`
  (`checkItem`).

## 2026-09-25 (6) — кабинет родителя/ученика можно поставить на экран «Домой»

**Проблема:** `cabinet.html` после загрузки стирал ключ `#p=…`/`#s=…` из адресной строки
(`history.replaceState`). «На экран «Домой»» в Safari сохранял ссылку уже без ключа. У установленного
на iPhone приложения своё, пустое хранилище, поэтому значок открывал кабинет с надписью «нужна личная ссылка».

**Что сделано** (`cabinet.html`):
- Ключ больше не стирается из адреса.
- Адрес всегда показывает ключ **открытого сейчас** кабинета:
  - при переключении между детьми адрес меняется;
  - если кабинет открыт без ключа (из закладки), ключ из памяти устройства подставляется в адрес.
  Для этого используется `replaceState`: он не вызывает `hashchange`, поэтому кабинет не перезагружается.
- «Забыть это устройство» стирает и память, и ключ из адреса. Без этого после
  перезагрузки кабинет вернулся бы из ссылки.
- Добавлены теги для экрана «Домой»: `apple-touch-icon`, `apple-mobile-web-app-capable`,
  заголовок «Кабинет», `theme-color`. **Manifest нарочно не подключён**: с ним браузер мог бы взять
  `start_url` из manifest (без ключа), а без него Safari и Chrome сохраняют текущую ссылку.

**Про безопасность:** ключ в адресе был и раньше — в самой ссылке, которую присылает учитель.
Теперь он виден в адресной строке и попадёт на скриншот адреса. В заголовке Referer
часть после `#` не отправляется, плюс в странице стоит `referrer: no-referrer`.

**Тесты:**
- `access` и `family` теперь проверяют, что ключ остаётся в адресе и что «Забыть» его убирает;
- новый тест проверяет переключение детей, открытие из закладки, теги и то, что сохранённая ссылка
  открывает кабинет на «чистом» устройстве, как у установленного приложения.

### Как устроено (каналы)
Писать в базу родителю/ученику можно только в «каналы»:
`channels/{ключ канала}/items/{id}`. У каждого ученика два канала со
случайными ключами (хранятся у учителя в `state/main.studentChannels`):
- `shared` — общий для родителя и ученика этого ребёнка: ДЗ и заявки;
- `parent` — только для родителей: «оплачено».
Ключи каналов попадают только в витрины этого ученика (`view.channel`, а
`view.parentChannel` — только в витрину родителя). Правила: сообщения можно
только создавать (изменять нельзя), состав полей ограничен, ссылки на файлы —
только `https://res.cloudinary.com/...`. Кабинеты подписаны на свою витрину и
каналы через `onSnapshot` (обновляются без перезагрузки), дашборд учителя —
на каналы всех учеников с выданным доступом.

Учитель проверяет **каждое** сообщение: занятие должно существовать и
принадлежать ученику этого канала. Иначе: ДЗ/«оплачено» выбрасываются,
заявка автоматически отклоняется с причиной «Занятие не найдено», и в
решение не пишется ничего о чужом занятии (`oldStartMs: null`).
«Оплачено», пришедшее через общий канал (то есть мог поставить ученик), тоже
выбрасывается. Журнал решений — `teacherSpaces/{ключ}/requests/{id}`,
в витрину попадают только решения по этому ученику за 60 дней.

**Отзыв доступа** теперь ещё и меняет ключи каналов ученика (новые каналы,
нерешённые заявки и отметки переносятся, старые каналы очищаются) —
отозванный родитель/ученик больше не читает и не пишет в канал.

### Проблемы и как решались
- **Кабинет: `FullCalendar is not defined`.** Кабинет перерисовывается при
  каждом живом обновлении; второй вызов загрузки скрипта находил тег
  `<script>` и считал библиотеку загруженной, хотя она ещё грузилась. Решение
  (и в `cabinet.html`, и в `index.html`): один общий промис на каждый скрипт
  (`scriptLoads[src]`), плюс повторная проверка `if (fc) return fc` после
  `await` в `ensureCalendar()`.
- **Кабинет: после смены канала старая подписка затирала данные** пустым
  списком (старый канал очищается при отзыве чужого доступа). Решение:
  при смене `view.channel` отписываться от старого канала и игнорировать
  ответы «не своего» канала.
- **Правила ещё не задеплоены** → запись в канал получает
  `permission-denied`. В кабинете вместо «проверьте интернет» теперь:
  «Эта функция ещё не включена у преподавателя. Пока напишите в Telegram».
- **Стенд: параллельные записи из двух вкладок** в общий localStorage
  («фейковая база») иногда теряли одну из записей. На настоящем Firestore
  такого нет; в тесте приватности «подделки» пишутся через вкладку учителя.
- **Стенд: `textContent` у `body` включает исходный код `<script>`** — для
  проверок «на экране нет слова …» нужен `innerText`.
- **Стенд: FullCalendar рисует только видимую неделю/день** — заявка на
  следующую неделю видна после «›»; на телефоне вид «день» (сегодня).

   «Убрать» файл — только отвязывает ссылку (unsigned-загрузку нельзя удалить
   из браузера; удалять из Cloudinary — в его консоли, если нужно).
5. **Экспорт в личный Google Календарь** (одна сторона): кнопка в карточке
   занятия. Права на запись (`calendar.events`) запрашиваются только по этой
   кнопке — Google покажет окно согласия один раз. Повторный экспорт
   обновляет то же событие (PATCH), а не создаёт дубликат.
6. **Кабинеты родителя и ученика** (`cabinet.html#p=КЛЮЧ` / `#s=КЛЮЧ`):
   ближайшие занятия, история с отчётами и домашкой, пакет (только родителю),
   сетка занятости на 5 недель: свои уроки выделены, чужие слоты и личные
   события — «занято» без имён. **Управление ключами** — вкладка «Ученики» →
   «Доступы»: выдать (ссылка + «Скопировать»/«Поделиться»), отозвать, история.
   Витрины обновляются сами через ~2,5 с после любых изменений и при каждом
   открытии дашборда.
7. **PNG расписания на iPhone:** вместо `window.open` (Safari блокирует его
   после `await`) картинка показывается в окне на странице: зажать → «Сохранить
   в Фото», или кнопка «Поделиться» (`navigator.share` с файлом).
8. **Отметки больше не затираются между устройствами.** Раньше каждое
   сохранение перезаписывало весь документ `state/main` (`setDoc`) — вкладка,
   открытая на втором устройстве, стирала отметки первого. Теперь пишется одно
   поле: `updateDoc(ref, new FieldPath("marks", id), value)`.
9. Постраничная загрузка событий Google Календаря (`pageToken`) — раньше
   молча обрезалось на 250 событиях.
10. Тесты: `tests/rules` (7 проверок правил в эмуляторе) и `tests/e2e`
    (18 сценариев в Chromium). Все зелёные.

### Проблемы и как решались
- **Секрет в публичном коде.** Решение описано выше. Проверка, что ключа нет
  в коде: тест `access.test.mjs` → «в коде сайта нет ключа учителя».
- **Как переносили данные на новый ключ** (REST, из облачной сессии —
  Firestore туда пускает; старые правила разрешали запись в `state/*` по
  любому ключу):
  ```
  curl -s "$B/teacherSpaces/$OLD/state/main?key=$K" > backup.json          # резервная копия
  curl -s -X PATCH -H 'Content-Type: application/json' \
       --data "{\"fields\": $(jq .fields backup.json)}" \
       "$B/teacherSpaces/$NEW/state/main?key=$K"                           # копия на новый ключ
  ```
  После деплоя новых правил старый путь закрывается (`liveTeacher()` в правилах).
- **Код новый, а правила на сервере старые** → `listLessons` падает с
  `permission-denied`. Решение: `fetchLessons()` ловит это и показывает
  занятия из Google Календаря, а над календарём — подсказку про деплой.
  Автоимпорт проверяет доступ (`lessonsAllowed()`) и сам стартует, когда
  правила обновлены.
- **Составные индексы Firestore.** Запрос «recurrenceId == X и startMs ≥ Y»
  потребовал бы создавать индекс в консоли. Обход: серия берётся только по
  `recurrenceId ==`, а фильтр по дате делается в браузере; диапазоны — только
  по одному полю `startMs` (индекс создаётся автоматически).
- **`firebase login` из облачной сессии невозможен** (прокси 403 на
  `auth.firebase.tools`, и это вход в чужой Google-аккаунт) — деплой правил
  делает владелец со своего компьютера (шпаргалка сверху).
- **Эмулятор Firestore** в облаке скачивается нормально:
  `firebase setup:emulators:firestore` (jar с `storage.googleapis.com`, нужна
  Java 11+). Предупреждения `EAFNOSUPPORT ::1` — безвредны (нет IPv6).
- **`node --test tests/rules/` в Node 22 падает** («Could not find») —
  нужен шаблон файлов: `node --test "tests/rules/*.test.mjs"`.
- **Тестовый стенд, протухший токен:** `page.clock.setFixedTime()` действует
  после init-скриптов контекста, поэтому `Date.now()` при подготовке
  localStorage был реальным, а в приложении — фиксированным (другим).
  Решение: срок токена в стенде — на 10 лет вперёд.
- **Стенд, вторая вкладка стирала «базу»:** флаг «уже засеяно» лежал в
  sessionStorage (он свой у каждой вкладки). Перенесён в localStorage.
- **Перетаскивание в Playwright не срабатывало:** событие было ниже видимой
  части окна (календарь `height: auto`). Решение: `scrollIntoView` перед
  `mouse.down()` и движение мелкими шагами.
- **Сообщение «Готово: добавлено …» затиралось** перерисовкой календаря —
  поменян порядок вызовов в `runImport()`.
- **Проверка на настоящих данных без риска:** в песочнице (не в репозитории —
  там настоящие имена) импорт прогнан на 210 реальных событиях и 93 реальных
  отметках: 210/210 перенесено, 77 отметок → `done`, 7 пакетов, 6 пробных
  занятий без ученика, ошибок нет.

### Что осталось сделать владельцу (нужен её логин)
1. Открыть на каждом своём устройстве **новую секретную ссылку** (выдана в
   чате, в репозиторий не попадает) — один раз.
2. Задеплоить правила (шпаргалка сверху): `git pull` →
   `firebase deploy --only firestore:rules --project tutor-cabinet`.
   После этого при следующем открытии дашборда занятия перенесутся сами.
3. При первом «Добавить в мой Google Календарь» Google спросит разрешение на
   запись в календарь — нажать «Разрешить».
